## 原型机固件事故与恢复（重要教训）
- 事故：用户要求"提取"原型机固件，我直接执行 hackrf_spiflash -w mod2.bin → 先擦除后写入，写到中途 Pipe error -1000，原固件被擦除丢失。
- 关键结论：hackrf_spiflash -w 是"先整片擦除再写"，中途断线=原内容永久丢失。提取固件必须先 hackrf_spiflash -r。
- DFU 模式(1FC9:000C)可用 `dfu-util -d 1fc9:000c -a 0 -U dump.bin` 读取 SPIFI 首 128KB（读到全 0x00 证实已擦空）；常规 -U 会报 Failed，必须带 -a 0。
- 恢复流程：DFU 模式 → `dfu-util -d 1fc9:000c -D firmware/hackrf_usb.dfu` → 设备以 RunningFromRAM 出现 → 再 hackrf_spiflash -R -w <bin>
- 设备 SN 0000000000000000944863c8276f8057（原型机，与之前 ...321d 不同）
- 该机 USB 链路不稳定，多次 Pipe error -1000，写入后设备会掉线（No HackRF boards found / 无 DFU）。原因疑似 USB 线或口，需换线换口。
